Guide d'installation

Harden Defense

Un laboratoire qui montre la différence entre un IDS, qui prévient, et un IPS, qui bloque. Ce guide t'amène de zéro jusqu'à la démonstration complète.

1 à 2 hla première fois
2 machinesUbuntu et Kali
8 étapesdont 1 facultative
Le principe

Une machine attaque, une autre se défend

Kali lance quatre attaques contre Ubuntu. Sur Ubuntu, deux sondes regardent le même trafic : Snort alerte seulement, Suricata peut bloquer. Le tableau de bord montre le résultat en direct.

Avant de commencer

Mes valeurs

Tape-les une fois : toutes les commandes de ce guide se mettent à jour, prêtes à copier. Tu les trouveras avec ip a sur Ubuntu à l'étape 4.

Pas à pas

Les huit étapes

  1. 1

    Créer le réseau privé

    C'est le câble virtuel entre Kali et Ubuntu. Ton ordinateur y est branché aussi, pour ouvrir le dashboard.

    VirtualBox

    Menu Fichier → Outils → Gestionnaire de réseau, onglet Réseaux hôtes uniquement, bouton Créer, puis coche Serveur DHCP. Les libellés varient un peu selon ta version de VirtualBox.
  2. 2

    Régler les deux machines

    Pour chaque machine : Configuration → Réseau. Deux cartes, dans cet ordre.

    MachineMémoireCarte 1Carte 2
    Ubuntu (défenseur)4 Go, 2 processeursNAT (internet)Réseau privé hôte
    Kali (attaquant)2 Go, 2 processeursNAT (internet)Réseau privé hôte
  3. 3

    Installer Ubuntu et Kali

    Ubuntu : installation normale, avec un nom d'utilisateur et un mot de passe. Kali : importe la machine déjà prête avec Fichier → Importer un appareil virtuel.

    Démarre les deux. Elles doivent avoir une adresse qui commence par 192.168.56. et pouvoir se joindre :

    Kali

    ping 192.168.56.101
  4. 4

    Installer Harden Defense sur Ubuntu

    Une seule commande installe Snort, Suricata et leurs règles ; la suivante prépare le dashboard. Compte quelques minutes.

    Ubuntu

    # l'IP et le nom de la 2e carte :
ip -4 -br addr show
# le projet :
sudo apt update && sudo apt install -y git
git clone https://github.com/atobouh/Harden-defense.git
cd Harden-defense
# les sondes, puis le dashboard :
sudo ./scripts/install_defender.sh enp0s8
./scripts/install_app.sh
  5. 5

    Démarrer en mode Surveillance

    Dans le premier terminal, démarre les sondes. Dans un deuxième terminal, lance l'application.

    Ubuntu

    # terminal 1
sudo ./scripts/lab.sh ids

# terminal 2
cd Harden-defense && ./scripts/run_app.sh
    Depuis ton ordinateur, ouvre http://192.168.56.101:5000. Le terminal affiche aussi un code à 6 chiffres : il sert à modifier les réglages depuis un autre appareil.
  6. 6

    Lancer les attaques depuis Kali

    Le script lance un contrôle de trafic normal, puis les quatre attaques, et dit pour chacune si elle est passée ou bloquée.

    Kali

    git clone https://github.com/atobouh/Harden-defense.git
cd Harden-defense/kali
./attack.sh 192.168.56.101 all http://192.168.56.101:5000
  7. 7

    Passer en mode Protection

    Suricata se met à bloquer. Attends environ 10 secondes qu'il démarre, puis relance exactement les mêmes attaques.

    Ubuntu

    sudo ./scripts/lab.sh ips

    Kali

    ./attack.sh 192.168.56.101 all http://192.168.56.101:5000
  8. 8

    Telegram et l'IA Facultatif

    Dans l'onglet Réglages du dashboard, tout est guidé. Rien n'est obligatoire : sans réglage, l'application utilise des explications intégrées.

    Telegram, en 3 temps

    1. Dans Telegram, parle à @BotFather, envoie /newbot, copie le token et colle-le.
    2. Envoie /start à ton bot, puis « Trouver mon compte ».
    3. « Envoyer un message de test ».

    L'IA, gratuite

    Crée une clé sur aistudio.google.com/apikey, colle-la, clique « Tester et enregistrer ». Une clé qui ne marche pas n'est pas enregistrée.

    Ton token Telegram et ta clé sont personnels : ne les publie jamais. L'application les garde dans data/settings.json, un fichier privé ignoré par git.
Résultats attendus

Ce que tu dois observer

Mesures faites sur un laboratoire de test. Refais-les sur tes machines : tes chiffres peuvent varier légèrement.

AttaqueMode SurveillanceMode Protection
Scan de portspassée aucun port filtréétouffée environ 440 ports sur 500 sans réponse
Bruteforce SSHpassée 15 connexions sur 15bloquée 5 connexions sur 15
Flood ICMPpassée aucune pertebloquée environ 50 % de pertes
Injection SQLpassée le site répondbloquée connexion coupée
Trafic normalOKOK aucun faux positif
Le scan montre une limite à expliquer : nmap sonde d'abord les ports courants (22, 80), qui passent avant que le seuil ne se déclenche. Le reste du scan est étouffé.
Si ça bloque

Les problèmes fréquents

Kali n'arrive pas à joindre Ubuntu

Depuis Kali, ping 192.168.56.101. Vérifie que les deux machines ont la carte 2 en « Réseau privé hôte » et que l'IP utilisée est celle de la 2ᵉ carte d'Ubuntu (ip a), pas celle du NAT (10.0.2.x).

Mon ordinateur n'ouvre pas le dashboard

Utilise l'IP de la 2ᵉ carte d'Ubuntu. Vérifie que ./scripts/run_app.sh tourne (deuxième terminal) et que le port 5000 n'est pas bloqué.

« Suricata : ERREUR » à l'installation

Lance sudo suricata -T -c /etc/suricata/suricata.yaml -v : la ligne en cause s'affiche. Envoie-la pour qu'on la corrige.

Le dashboard reste vide

Vérifie sudo ./scripts/lab.sh status, puis relance une attaque depuis Kali. Les alertes n'apparaissent que quand une attaque se produit.

Le script d'attaque dit « Le scan n'a pas pu s'exécuter »

Il manque peut-être nmap : sudo apt install nmap. Sans sudo sans mot de passe, Kali utilise un scan par connexion : c'est normal.

« Clé refusée » ou « Limite gratuite atteinte »

Recopie la clé en entier, sans espace, ou crée-en une nouvelle. Pour la limite : attends une minute, l'application réessaie seule et garde les textes intégrés en attendant.

Telegram : « Rien reçu pour l'instant »

Ouvre ton bot dans Telegram, envoie-lui /start, puis reclique sur « Trouver mon compte ».

Sans machine virtuelle

Voir seulement le dashboard

En dix minutes, sur Windows, Mac ou Linux, avec des données de démonstration. Il faut Python 3.10 ou plus récent (sous Windows, coche « Add Python to PATH »).

Windows (PowerShell)
git clone https://github.com/atobouh/Harden-defense.git
cd Harden-defense
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m harden.demo --reset
.venv\Scripts\python -m harden.dashboard

Puis ouvre http://localhost:5000. Arrêt : Ctrl + C.

Mac ou Linux
git clone https://github.com/atobouh/Harden-defense.git
cd Harden-defense
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m harden.demo --reset
.venv/bin/python -m harden.dashboard

Puis ouvre http://localhost:5000. Arrêt : Ctrl + C.
